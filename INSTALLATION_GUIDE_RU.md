# DAG Orchestrator Desktop v2.3.0 — инструкция

DAG Orchestrator Desktop v2.3.0 — установщик для Windows 11
Разработчик: Давид Пагава (David Pagava)
Авторские права: © 2026 David Pagava
Назначение
Один ZIP для переноса на другой Windows 11. Двойной щелчок по BAT запускает предварительную проверку, установку MCP для обычного Claude Desktop Chat, проверку или удаление. Команды PowerShell вручную вводить не нужно.

Папка комплекта на вашем компьютере: D:\DAG\INSTALL. Распакуйте файлы в корень этой папки, чтобы находились файлы INSTALL-DAG.bat, bootstrap.ps1, installer_engine.py, каталог mcp, каталог PluginTemplate, payload-manifest.json.

Важно: это ZIP с BAT/PowerShell/Python, а не подписанный .exe/.msi. Он не получил сертификат цифровой подписи Microsoft. Антивирус/политика организации может ограничить запуск; не обходите корпоративные запреты. Установку плагина в аккаунт Claude нельзя гарантированно автоматизировать через поддерживаемый публичный интерфейс, поэтому после установки MCP требуется одно действие вручную.
Порядок (на втором компьютере)
1. Установите и один раз запустите Claude Desktop, войдите в свой аккаунт. После этого завершите приложение через значок возле часов → Выход/Quit. Не оставляйте Claude работать при изменении конфигурации.
2. Распакуйте архив в D:\DAG\INSTALL (или любую папку). Не запускайте BAT из ZIP без распаковки.
3. Дважды запустите CHECK-FIRST.bat. Он проверит Python 3.10+, набор файлов и конфигурацию Claude. Никаких записей в Claude не производится. Если Python не найден — установите Python с https://www.python.org/downloads/windows/ и повторите.
4. Дважды запустите INSTALL-DAG.bat. Установщик сам найдёт активную конфигурацию. Для Windows MSIX/Microsoft Store он определит установленный пакет через Get-AppxPackage и выберет путь %LOCALAPPDATA%\Packages\<активный Claude package family>\LocalCache\Roaming\Claude\claude_desktop_config.json. Для классической установки используется %APPDATA%\Claude\claude_desktop_config.json.
5. Убедитесь, что появилось INSTALL OK, и запишите расположение резервной копии. Установщик сохраняет memory, filesystem, остальные MCP и пользовательские настройки, изменяя только mcpServers.dag-orchestrator-desktop.
6. Дважды запустите VERIFY-DAG.bat. Результат VERIFY OK означает: конфигурация записана, установленный server.py отвечает MCP, ZIP плагина проверен. Это ещё не означает, что Claude реально увидел сервер.
7. Запустите Claude Desktop и откройте Настройки → Разработчик, найдите dag-orchestrator-desktop со статусом «Выполняется/Running». В обычном Claude Chat можно дополнительно проверить dag_create и dag_status на учебном графе.
8. Для Claude Cowork / Claude Code откройте Плагины → Добавить → Загрузить плагин и выберите D:\DAG\INSTALL\DAG-Orchestrator-CLAUDE-PLUGIN-ready.zip. Если ZIP нельзя сохранить в папке установщика, программа напечатает путь к другой копии под %LOCALAPPDATA%\DAGOrchestratorDesktop.
9. На тестовой папке выполните граф A → (B,C) → D. Подтвердите наличие инструмента dag_* и реальную работу субагентов. Нельзя считать наличие плагина в списке доказательством работы инструмента.
4. Что сказать Claude, чтобы включить DAG Orchestrator в работу
После установки MCP и плагина откройте Claude Desktop (Cowork или Claude Code). Для большой задачи разработки используйте исходное название Skill: dag-orchestrator-desktop. Оно не переименовано; отдельный Skill /dag не добавлялся.

Если интерфейс предлагает команду /dag-orchestrator-desktop, выберите её. В некоторых режимах команды плагинов отображаются с префиксом самого плагина; если такая команда не показывается, просто напишите «Используй Skill dag-orchestrator-desktop и MCP-инструменты dag_*». Не считайте отсутствие подсказки доказательством ошибки MCP — проверьте список инструментов отдельно.

Готовый запрос для копирования:
Используй установленный Skill dag-orchestrator-desktop и инструменты MCP dag_*. Сначала изучи мой проект и составь DAG-план с зависимостями. Раздели независимые работы между доступными субагентами dag-implementer, dag-test-engineer и dag-reviewer; если среда позволяет, запускай независимые этапы параллельно. Не допускай одновременного изменения одних и тех же файлов. Перед началом каждого этапа проверяй зависимости через MCP. Сохраняй существующую функциональность, запускай реальные тесты и не отмечай задачу завершённой без подтверждённого результата. Если MCP или субагенты недоступны, честно скажи об этом. В конце дай короткий отчёт о выполненных этапах, тестах и известных ограничениях. Моя задача: [ОПИШИТЕ ЗАДАЧУ].

Для простых вопросов и мелких изменений DAG не обязателен: попросите Claude решить их обычным способом.
5. Ежедневное использование плагина
1. Откройте Claude Desktop и выберите папку нужного проекта. На новом проекте сначала работайте с резервной копией.
2. Поставьте задачу своими словами; при необходимости добавьте: «Используй dag-orchestrator-desktop» или вызовите доступную команду Skill.
3. Для сложной разработки Claude должен составить граф зависимостей, назначить независимые этапы разным субагентам и контролировать их через доступные dag_* MCP-инструменты.
4. При выдаче разрешений проверяйте, какие файлы и команды будет менять Claude; для важных проектов используйте контроль версий и резервные копии.
5. По завершении попросите: «Покажи статус DAG, результаты реальных тестов, незавершённые этапы и итоговый отчёт».
Как проверить, что плагин действительно используется: в ходе выполнения должны быть реальные обращения к инструментам dag_create, dag_claim, dag_complete / dag_fail и dag_status. Одного текста «использую DAG» недостаточно.

Ограничение: MCP-сервер контролирует состояния задач, зависимости, блокировки и восстановление; сам по себе он не запускает субагентов и не проверяет тесты проекта. Это делают доступные функции Claude и выбранные инструменты. checks_passed в MCP — сообщение исполнителя, а не независимый результат запуска тестов.
Требования и ограничения
- Windows 11 (x64; другие архитектуры и Windows 10 не испытаны пользователем).
- Claude Desktop установлен и его конфигурация создана первым запуском.
- Python 3.10+ установлен, доступен через py.exe, python.exe или python3.exe. Установщик проверяет версию и записывает полный путь к python.exe в конфигурацию Chat и готовый Plugin ZIP. Если Python отсутствует, установка останавливается без изменения настроек.
- Скрипт не требует прав администратора, не загружает код из интернета, не устанавливает программы silently и не изменяет global ExecutionPolicy; -ExecutionPolicy Bypass действует только в запускаемом PowerShell-процессе и может быть запрещён корпоративной политикой.
- Для Cowork потребуется разрешённая аккаунтом/организацией установка локальных плагинов. Если платформа ограничивает доступ плагина к внешнему Python, его MCP может не запуститься: проверяйте на компьютере.
Что изменяет установщик
- Создаёт/обновляет %LOCALAPPDATA%\DAGOrchestratorDesktop\server.py (локальный MCP).
- Создаёт %LOCALAPPDATA%\DAGOrchestratorDesktop\DAG-Orchestrator-CLAUDE-PLUGIN-ready.zip с актуальным абсолютным путём к Python и правильными /-разделителями ZIP.
- Создаёт копию ZIP в папке установщика, если она доступна для записи.
- Перед изменением JSON создаёт рядом резервную копию claude_desktop_config.json.backup-DAG-....
- Внутри выбранного JSON добавляет/обновляет одну запись mcpServers.dag-orchestrator-desktop. Существующие секции и другие подключения сохраняются по содержимому, но формат отступов JSON может поменяться.
- Реальные состояния и события DAG хранятся отдельно по умолчанию в %USERPROFILE%\.dag-orchestrator-desktop\state и не трогаются установщиком.
Если что-то пошло не так
- Python 3.10+ not found: установите официальный Python и запустите снова. Никаких установок из непроверенных сайтов.
- Claude config ... not found: запустите Claude Desktop один раз и зайдите в аккаунт; если стоит Microsoft Store Claude — убедитесь, что приложение установлено для текущего пользователя Windows.
- more than one / несколько MSIX-конфигураций: установщик не угадывает активную конфигурацию, а безопасно останавливается. Нужна ручная диагностика.
- config invalid JSON / повторяющиеся ключи: исправьте собственную конфигурацию или восстановите предыдущую вручную. Установщик ничего не перезаписывает при ошибке JSON.
- Python... in ZIP: ZIP для Cowork генерируется ПОСЛЕ установки; нельзя просто загрузить исходную папку PluginTemplate или ZIP от другого компьютера без проверки.
- Zip file contains path with invalid characters: выберите генерированный установщиком ZIP ...-ready.zip вместо ZIP, сделанного ZipFile.CreateFromDirectory на Windows. Установщик записывает имена с /.
- Плагин не видит dag_*: снимок его присутствия недостаточен; проверьте разрешения, доступ Python и настройки Claude.
- Если Claude постоянно перезаписывает конфигурацию, перед редактированием полностью закройте его, затем повторите установку.
Переустановка / откат / удаление
- Повторный запуск INSTALL-DAG.bat обновляет только свою запись и код; перед этим создаётся новая резервная копия. Если запись с тем же именем принадлежит другому пути, установщик отказывается её перезаписывать.
- UNINSTALL-DAG.bat создаёт резервную копию конфигурации и удаляет только запись Chat MCP. Установленные копии кода, сформированный Plugin ZIP и DAG-графы сохраняются для восстановления. Плагин Cowork удаляется вручную через интерфейс Claude → Плагины.
- Для полного удаления оставшихся файлов пользователь может отдельно удалить %LOCALAPPDATA%\DAGOrchestratorDesktop, но не удаляйте %USERPROFILE%\.dag-orchestrator-desktop\state, если нужны предыдущие DAG-графы.
- Резервную копию файла JSON можно восстановить вручную после полного закрытия Claude Desktop. Не копируйте резервные копии с токенами или секретами в публичные репозитории.
Что программа не делает
- Не устанавливает Python без разрешения и не меняет системные PATH / ExecutionPolicy.
- Не устанавливает Claude Desktop и не входит в аккаунт за пользователя.
- Не загружает плагин в аккаунт Claude автоматически.
- Не запускает субагентов: это делает Claude. DAG MCP ведёт состояние, зависимости и блокировки, но сам не выполняет проектные задачи и не проверяет checks_passed независимо.
- Не очищает пользовательские DAG и не удаляет чужие MCP-серверы.
Проверки релизного комплекта
Перед переносом проверены целостность ZIP, корректность manifest, тесты Python-движка установщика и создание Plugin ZIP с POSIX-путями. Реальный запуск BAT, PowerShell, MSIX-конфигурации и соединение Claude на втором Windows 11 ещё предстоит проверить. Результат этого теста нельзя заменять Linux-моделированием.
